### 1. Общая идея. 

**Предметная область:** Система автоматизированной обработки и загрузки коротких вертикальных видео.

**Проблема:** Чтобы взять исходное горизонтальное видео и превратить его в серию коротких вертикальных постов, нужно выполнить целый конвейер сложных действий. Программа должна: проверить файл, узнать его длительность через `ffprobe`, нарезать видео на куски по 15 или 30 секунд, применить сложные фильтры обрезки (`crop`) и масштабирования (`scale`) через `ffmpeg`, а затем отправить каждый кусок на сервер запросом через системный `curl`.

Если писать всё это напрямую в обработчике кнопки (как показано в реализации без паттерна), мы сталкиваемся с классической проблемой **«Божественного объекта»** и спагетти-кода. Форма начинает знать всё обо всём: она управляет консольными командами, следит за циклом нарезки, генерирует имена для временных файлов и вручную удаляет их.

**Почему это плохо?**
Во-первых, код интерфейса раздувается до невероятных масштабов. Во-вторых, ручное управление временными файлами в UI очень опасно: если при загрузке 2-й части отключится интернет, цикл прервется, и на жестком диске навсегда останется лежать временный мусор. Форма просто не должна заниматься низкоуровневой логикой работы с видео и сетью.

**Цель:** Разработать структурную архитектуру с помощью паттерна «Фасад», чтобы скрыть сложность взаимодействия с консольными утилитами (FFmpeg, cURL) и предоставить клиенту (интерфейсу) один простой метод для запуска всего конвейера.

### 2. Решение: как используется паттерн в вашем проекте.
Я внедрил структурный паттерн **Facade (Фасад)**. Вместо того чтобы заставлять форму самостоятельно дергать классы валидации, нарезки и загрузки, я создал единую точку входа, которая берет всю эту работу на себя.

**Как это работает в коде:**
*   **Подсистемы (`FileValidator`, `VideoEditor`, `NetworkUploader`, `CoverExtractor`):** Это основные функции нашего приложения. Они инкапсулируют в себе вызовы `std::system` с жесткими аргументами командной строки. Они ничего не знают друг о друге и об интерфейсе. Например, `VideoEditor` просто берет входной файл и режет его, ему всё равно, откуда этот файл взялся.
*   **Фасад (`TikTokFacade`):** Класс-оркестратор. Он содержит внутри себя объекты всех подсистем. У него есть ровно один публичный метод: `ProcessAndUpload()`. Внутри этого метода скрыт сложный цикл: фасад сам узнает длину видео, сам режет его на части, сам формирует описания (добавляя к тексту "Part 1", "Part 2"), загружает их в сеть.
*   **Клиент (`MyForm`):** Графический интерфейс. Ему больше не нужно собирать команды для FFmpeg. Он просто собирает текст из TextBox'ов и говорит фасаду: «Вот видео, вот текст, нарежь по 15 секунд и загрузи».

### 4. Вывод: как внедрение паттерна повлияло на работу программы.

В реализации **без паттерна** код кнопки запуска выглядел как кошмар. Логика UI была намертво перемешана с консольными скриптами:
```cpp
FileValidator v; VideoEditor ed; CoverExtractor ce; NetworkUploader up;
if (v.CheckFile(path)) {
    int total = v.GetDuration(path);
    ok = true;
    for (int s = 0, p = 1; s < total; s += duration, p++) {
        std::string vp = "np_part_" + std::to_string(p) + ".mp4";
        std::string cp = "np_part_" + std::to_string(p) + ".jpg";
        if (ed.CutAndRotate(path, vp, s, duration)) {
            ce.CreateCover(vp, cp);
            if (!up.Upload(vp, caption + " (Part " + std::to_string(p) + ")", "http://100.69.137.26:8000/api/upload")) ok = false;
            std::remove(vp.c_str()); std::remove(cp.c_str());
        }
    }
}
```

После внедрения **паттерна Фасад** вся эта простыня кода в форме схлопнулась до элегантных двух строчек:
```cpp
TikTokFacade facade;
ok = facade.ProcessAndUpload(path, duration, caption);
```

**Итоги внедрения:**
1.  **Разделение ответственности (Single Responsibility).** Форма теперь занимается только тем, чем должна: рисует кнопочки и показывает MessageBox. Вся логика перенесена в Фасад.
2.  **Безопасность.** Риск того, что временные файлы засорят память компьютера из-за ошибки в UI, полностью исчез. Уборка мусора инкапсулирована внутри Фасада.
3.  **Масштабируемость.** Если завтра мы решим добавить подсистему наложения водяных знаков, код формы **вообще не изменится**. Нужно будет добавить пару строк только внутрь класса `TikTokFacade`.

Паттерн Фасад идеально подошел для изоляции сложного, многоступенчатого конвейера обработки медиа от пользовательского интерфейса.
